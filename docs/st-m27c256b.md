# ST M27C256B windowed DIP28 speed grades

**Existing support suffices:** select `M27C256B@DIP28` for both
`M27C256B-10F1` and `M27C256B-12F1`. These full ordering codes are not separate
catalog entries or aliases. No production code, duplicate profile, or algorithm
change is needed for these grades.

[ST's M27C256B datasheet, May 2006 Rev 2](https://www.farnell.com/datasheets/1695222.pdf)
(manufacturer document mirrored by Farnell) establishes:

| Marking | Access time | Package / temperature | Select |
| --- | --- | --- | --- |
| M27C256B-10F1 | 100 ns | Windowed FDIP28W / 0–70 °C | M27C256B@DIP28 |
| M27C256B-12F1 | 120 ns | Windowed FDIP28W / 0–70 °C | M27C256B@DIP28 |

The ordering table is on page 22. Both grades have 32,768 × 8 storage and
electronic signature `20 8D`. The family programming section (pages 9–10)
specifies PRESTO II, 100 µs pulses, VPP 12.75 V and programming VCC 6.25 V.
The access-time suffix does not select another programming algorithm.
Windowed parts require external UV erasure (page 11); they are not electrically
erasable Winbond parts. These commercial temperature grades do not establish
vehicle suitability.

## Existing T48 evidence

The [XGecu T48 V12.78 device list](https://www.epromirok.hu/downloads/t48_list.pdf#page=234)
lists `M27C256B @DIP28`. The catalog already matches the exact
`INFOIC2PLUS` record in
[MiniPro a8efaedc236c1d9718bd28299dfbb99536b010ff](https://gitlab.com/DavidGriffith/minipro/-/blob/a8efaedc236c1d9718bd28299dfbb99536b010ff/infoic.xml):
protocol `0x07`, variant `0x3211`, raw voltages `0x5070`, chip info `6`,
pin map `0x0c16`, pulse delay `100`, flags `0x68`, ID `0x208d`,
32,768 bytes and 28 pins. Raw voltages are firmware encodings, not direct volts.
T48 firmware owns the electrical programming sequence.

Read and save a backup first. After any needed external UV erase, use an exact
32,768-byte image with `erase: false`, `verify: true`; the library blank-checks
the whole chip immediately before programming. The browser API rejects electrical
erase requests with `InvalidInput` (native Zig reports `EraseUnsupported`);
any nonblank byte fails with `TargetNotBlank` before
the first programming payload. WorkbenchOS derives these choices from the profile
and additionally compares a separate full readback's SHA-256.

The existing descriptor tests and new compiled-Wasm/simulated-USB tests cover
the shared profile, full-size blank check/write/verify, electrical-erase rejection,
and a nonblank final byte. These are source/software checks only. Neither exact
ST variant has been physically tested in this task.
